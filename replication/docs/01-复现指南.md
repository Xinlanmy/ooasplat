# 复现指南

从一台干净的 Apple Silicon Mac 到跑出第一个 `final.ply`。

> 适用于 macOS 15+ / arm64。上游另有 Windows 与 Ubuntu 版本，本仓库的脚本只覆盖 macOS。

---

## 一、三个依赖

| 依赖 | 版本 | 说明 |
|---|---|---|
| Node.js | 22.12+ | 前端构建与 Tauri CLI |
| Rust | stable（本机实测 1.100.0） | 仓库根目录的 `rust-toolchain.toml` 会锁定版本，rustup 会自动补装 |
| Xcode Command Line Tools | — | 提供 clang 与链接器，`xcode-select --install` |

Rust 用 rustup 安装（用户级，不需要 sudo）：

```bash
curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh -s -- -y --profile minimal
source "$HOME/.cargo/env"
```

若官方源反复断流（国内常见），改用镜像：

```bash
export RUSTUP_DIST_SERVER=https://mirrors.ustc.edu.cn/rust-static
export RUSTUP_UPDATE_ROOT=https://mirrors.ustc.edu.cn/rust-static/rustup
rustup toolchain install 1.100.0 --profile minimal -c rustfmt -c clippy
```

## 二、准备引擎（本仓库最容易卡住的一步）

```bash
./replication/tools/setup.sh
```

这个脚本做两件事：`npm ci` 装前端依赖；从官方 dmg 中提取四个引擎到 `engines/macos/arm64/`。

**为什么不能直接用 `npm run setup:engines`：**

上游 macOS 的引擎清单 `engines/manifest.macos.json` 里，分发归档的哈希字段是 `null`，`buildStatus` 为 `pending-first-build-and-hash-lock`。安装脚本按设计会拒绝执行。README 也明确写了这一点。

**为什么从 dmg 提取而不是自己编译：**

发布包里已经打包了四个引擎，版本与应用完全一致：

| 引擎 | 版本 | 来源 |
|---|---|---|
| FFmpeg / FFprobe | 8.1.2 | Apple arm64，LGPL shared |
| COLMAP | 4.2.1 | CPU + Ceres，无 CUDA |
| OOOBrush | ooo-v1.0.0 | 无界面 CLI (`brush_app`) |

自己编译 FFmpeg 要处理 LGPL 组件边界，编译 Brush 要拉 200+ 个 Rust crate，都不如直接取现成的。脚本会校验 dmg 的 SHA-256（`b4159bb8…c1037`）后再解包。

> **FFmpeg 必须是 8.x。** 抽帧阶段会无条件传 `-stats_enc_pre`，这是 FFmpeg 7.1 才引入的参数；用 6.x 的静态版会直接报 unknown option。

## 三、跑起来

**桌面应用：**

```bash
./replication/tools/run-dev.sh
```

**命令行（推荐用于批处理）：**

```bash
cargo build --release --manifest-path src-tauri/Cargo.toml --bin splatstudio

./src-tauri/target/release/splatstudio generate <视频路径> \
  --quality balanced \
  --projects-root "$(cd .. && pwd)/splat-projects"
```

> `--projects-root` **必须是绝对路径**，相对路径会报 `INVALID_PATH`。

其他子命令：

```bash
splatstudio health                 # 校验四个引擎
splatstudio probe <视频>            # 读元数据
splatstudio plan <视频> --quality balanced   # 只算抽帧计划，不执行
splatstudio generate <视频> --inspect        # 打印完整计划后退出
```

`plan` 特别有用——它能在几秒内告诉你「抽多少帧、目标帧率、补帧池多大」，不用等半小时才发现参数不合适。

## 四、项目目录

跑一次生成后，`<projects-root>/<时间戳>_<源文件名>_<id>/` 下会得到：

```
project.json            档位、状态、耗时
source/                 源素材副本
state.json              断点续跑用的流水线状态
logs/
  activity-*.log        结构化事件流（含 SplatBudget 记录）
  colmap.log            COLMAP 原始输出
  brush.log             Brush 训练日志（含每 200 步的 Refine 记录）
work/
  frames/               抽出的训练帧（含 Bridge 补的帧）
  masks/                透明素材的 alpha 遮罩
  colmap/authoritative/ 最终稀疏模型（cameras.bin / images.bin / points3D.bin）
  brush/                训练数据集与中间产物
final.ply               最终模型
```

`work/colmap/authoritative/` 是关键——`replication/tools/preview_ply.py` 就是从这里读真实相机位姿。

## 五、验证结果

```bash
python3 replication/tools/preview_ply.py <项目目录> -n 4
```

输出一张对比图：左为原始帧，右为按**同一相机位姿**渲染的模型。如果两者位置对不上，说明重建有问题；如果对上了但很糊，说明是素材信息量不足。

注意这个工具只为验证而写，省略了球谐高阶项与逐像素排序，噪点会比应用内预览多。**画质上限请以应用内预览为准。**

## 六、批量汇总

```bash
python3 replication/tools/collect_stats.py <projects-root> -o runs.csv
```

从每个项目的日志里提取注册数、平均轨迹长度、splat 上限、实际 splat 数、耗时，输出 CSV。默认只统计已完成的项目，加 `--all` 包含中断的。
